# Codex Windows Doctor

Audit first. Do not change files, processes, registry, environment variables, login state, plugins, or applications.

## Run the snapshot

Explain what will be read, then run `scripts/Get-CodexWindowsSnapshot.ps1`. Pass project roots only when the user placed those projects in scope. Save JSON only when the user wants a support artifact.

The script intentionally reports secret-variable presence without values and scans config key names without returning their assigned values.

## Interpret the result

Classify every finding as:

- **Confirmed active problem:** currently affects Codex.
- **Potential conflict:** needs a targeted verification.
- **Historical only:** present in sessions, backups, or disabled directories but not loaded.
- **Expected current state:** normal files generated by the active installation.
- **External/product boundary:** cannot be safely fixed by local cleanup.

Do not label `.codex`, AppX state, runtime caches, or running Codex processes as residue merely because they exist while Codex is installed.

Read [references/report-schema.md](references/report-schema.md) before writing the report.

## Route the next step

- Route old API/provider history to `$codex-api-to-chatgpt-migration`.
- Route an approved local fix to `$codex-windows-repair`.
- Route Chrome-only failures to `$codex-chrome-doctor`.
- Route missing history to `$codex-session-restore`.
- If no user-side fix is supported, provide a redacted report and stop.
